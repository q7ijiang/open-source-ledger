## 一、数据说明

- 两个文件均为**完整 CycloneDX 1.7 BOM**（各 7 个组件：3 个 AI 模型 + 1 个数据集 + 3 个 Python 库），可直接作为 delta_engine 的输入。
- 模拟故事：项目微调了 Llama-2-7b 基座模型（→ llama2-finetune-demo → llama2-chat-demo），并使用了 instruction-dataset 训练数据。
- t0 → t1 之间**只注入两处许可证变化**（已验证：除许可证外，组件结构、purl、revision、血缘关系完全一致）：

| 资产 | t0 许可证 | t1 许可证 | 场景 |
|---|---|---|---|
| meta-llama/Llama-2-7b（基座） | Apache-2.0 | Llama-2-Community | S1：宽松 → 严格 |
| instruction-dataset（数据集） | CC-BY-4.0 | CC-BY-NC-4.0 | S4：添加非商业限制 |

## 二、与接口约定 v0.3 的衔接

1. **t0/t1 保持标准 CycloneDX 输入格式**（purl / bom-ref / pedigree.ancestors / modelCard.datasets 原始形态）；`canonical_id`、`entity_key` 等版本化标识由 A 的 `bom_adapter.build_asset_identifiers()` 在解析时生成，不需要在输入里手工拼。
2. 血缘表达使用 CycloneDX 标准字段：
   - 微调关系 → `pedigree.ancestors[]`（finetune）
   - 训练数据关系 → `modelCard.modelParameters.datasets[]`
   - 普通依赖 → `dependencies[]`
3. **边证据等级口径**：按 v0.3，HF 字段产生的血缘边统一为 **B 级**（BOM 为工具产物）。本数据不预设证据等级，由上游解析层统一标注。

## 三、B 跑验收时的预期

- delta_engine 应产出 **2 个 `license_changed` 事件**（evt：Llama-2-7b、instruction-dataset），seed 指向变化资产自身（边变更事件 seed 取 edge.target，B 已修）。
- propagation 应沿血缘传播：Llama-2-7b → llama2-finetune-demo → llama2-chat-demo；instruction-dataset → llama2-finetune-demo。
- 验收判据：`path_certificates > 0`，且报告能呈现三种判定。
- **B 输出结构（C 的 report_enhanced.py 已按此对齐）**：`propagated.json = {"events": [...], "path_certificates": [...]}`
  - 事件：`event_id / seed / change_type / before / after / path / evidence_level / decision`（before/after 为对象，含 canonical_id、entity_key、license、purls、snapshot_id、merge_status、reason_code、rule_version）
  - 路径证书：`certificate_id / affected / change_type / hop_count / weakest_evidence / decision / termination / missing_ancestor / path_fingerprint`
- 演示样例：`module11-report_enhanced/demo_propagated_v03.json`（3 事件 + 3 证书，覆盖三种判定）。
