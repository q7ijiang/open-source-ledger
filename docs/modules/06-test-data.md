## 为什么要做

1. 基础层 4 个模块（2/3/4/5）需要一个共享输入做联调，避免各写各的。
2. 真实 cdxgen 输出的证据形态（evidence 无 URL、identity 在 methods[].value）需要被各模块识别，用合成数据把这些边界显式化。
3. 双 purl 模型（bert）、高风险许可证、无许可证组件都是验收必测点。

## 具体怎么做

1. 参照 cdxgen 12.8.4 真实输出结构构造 12 个组件：8 个 library + 3 个 model + 1 个 dataset。
2. 埋入关键场景：bert 双 purl 重复（8/9）、GPL/AGPL 高风险（6/7）、gpt2 训练数据集血缘（10/11）、无许可证（12）。
3. 编写场景覆盖清单（12 行）与各模块验证要点。

## 验证

- 组件 8/9 应合并为 1 个资产（11 组件 → 10 资产）。
- 组件 7/10/11 的 evidence 补全走三类分支（externalReferences / methods[].value / 降级 L1）。
- GPL/AGPL 命中高风险规则；无 license 输出"待人工确认"。
