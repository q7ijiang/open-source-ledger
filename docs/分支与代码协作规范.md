# 开源账本分支与代码协作规范

## 1. 分支策略

| 分支 | 用途 | 负责人 |
|---|---|---|
| main | 稳定可验收版本，所有最终交付以 main 为准 | A、B、C 共同维护 |
| dev-A | 数据管道开发分支 | A |
| dev-B | 算法核心开发分支 | B |
| dev-C | 交付与验证开发分支 | C |

## 2. 合并规则

1. 禁止直接向 main 推送代码。
2. 禁止自己评审并合并自己的 PR。
3. 每个 PR 至少需要 1 名其他成员完成 Review。
4. 涉及接口约定的变更，至少需要 2 名其他成员确认。
5. PR 合并前必须满足：代码可运行、测试可复现、文档已同步、无密钥泄露。

## 3. 代码规范

1. Python 代码使用 4 空格缩进，遵循 PEP 8。
2. JSON 字段必须与 `docs/接口约定.md` 保持一致。
3. 网络请求必须有超时、异常处理和降级路径。
4. 证据链补全失败时必须记录真实状态（如 network_error），不得伪造证据。
5. 提交信息格式：`feat(module): summary`、`fix(module): summary`、`docs(module): summary`

## 4. 禁止事项

1. 禁止直接推送 main。
2. 禁止强制覆盖他人的 dev 分支。
3. 禁止用猜测结果冒充官方证据。
4. 禁止提交 Token、密钥、私有模型权重或大型缓存。
5. 禁止绕过 `docs/接口约定.md` 自定义字段。

## 5. 免费私有仓库限制

由于 GitHub 免费私有仓库无法强制启用分支保护，main 不可直接推送、必须 PR Review 等规则无法由平台强制执行。A、B、C 必须自觉遵守本规范，并在每周验收时检查是否存在违规合入。
